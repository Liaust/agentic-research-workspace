# Security policy

## Supported version

The latest released version is the supported version of this experimental
project. No long-term support window is currently promised.

## Reporting a vulnerability

Use the repository host's private security-reporting channel when it is
available. If no private channel is available, open a minimal public issue
requesting private contact without disclosing exploit details, credentials,
local paths, private URLs, or source material.

Reports should identify the affected version, expected impact, and a minimal
reproduction using synthetic data. Do not test against systems or data you do
not own or have permission to assess.

## Sensitive research material

Third-party papers, exact evidence spans, private graph records, and ignored
run artifacts are intentionally outside this public projection. Their presence
in a candidate is a release-integrity failure even when it is not a traditional
software vulnerability.
